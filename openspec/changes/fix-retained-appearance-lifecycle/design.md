## Context

`appearanceResolution=await-response` 的抓牌或出牌动画在完成后会把视觉所有权从事件计划转移到 `held:<cardId>`，使大牌持续显示到响应窗口裁决。当前释放动作分散在正常事件播放和部分结果状态处理里，因此只有真正进入 `playOnlineEvent` 的 `unclaimed`、吃碰招踏和胡能够可靠释放；`circle-loss`、`draw-round`、`settlement`，以及 `selfAcked`、重连积压跳播、重复事件对齐等不播放动画的分支会绕开清理。

双真人两 AI 房间暴露了第二条稳定路径：服务端对 `after-grouping` 只要求动作席位回执，另一位真人收到相同吃牌事件时为 `selfAcked=true`。该客户端跳过吃牌动画，也跳过了“吃牌已消费当前出现牌”的视觉语义，旧牌因而残留。

修复必须同时满足两个约束：跳过动画不等于跳过状态收尾；单个 `pass` 或仍有效的响应窗口又不能提前清除出现牌。

## Goals / Non-Goals

**Goals:**

- 为 retained 出现牌建立可复用、幂等的语义收尾入口。
- 让正常播放、`selfAcked`、重连/积压跳播、重复事件和结果状态恢复得到一致的最终画面。
- 仅在权威语义已经消费、归位或终止当前出现牌时释放，保留仍处于响应窗口中的牌。
- 用双客户端和终局场景回归测试覆盖已确认的两类问题。

**Non-Goals:**

- 不改变服务端吃碰招踏、胡、进圈或流局规则。
- 不改变动画屏障的必需回执席位选择，也不要求所有真人播放所有动画。
- 不改变事件协议、`appearanceResolution` 值或 WebSocket 消息格式。
- 不调整动画时长、牌面样式、音效或 AI 策略。

## Decisions

### 1. 以事件语义统一结束 retained 生命周期

在动画控制器提供幂等的 retained 出现牌收尾能力，由正常播放与不播放事件的在线分支共同调用。事件分为：

- 保留：`draw`/`discard` 且 `appearanceResolution=await-response`、尚未完成全部响应的 `pass`。
- 归位或消费：`unclaimed`、`chi`、`peng`、`zhao`、`ta`、`hu`。
- 终止并清场：`circle-loss`、`draw-round`、`settlement`。

对于携带 `card.id` 的归位事件优先核对当前 held card id；凑牌与终局事件表示权威序列已经结束当前响应牌，可幂等释放当前 held 视觉。正常播放仍负责具体运动和特效，不播放分支只应用视觉收尾，不播放动画或音效。

备选方案是在每个在线时间线分支分别调用 `releaseHeldAppearance`。该方案容易再次漏掉新增分支，也无法集中表达 `pass` 必须保留的例外，因此不采用。

### 2. `selfAcked` 表示免回执，不表示忽略事件语义

在线控制器继续跳过不要求本客户端观看的完整动画，但在清理本地预演之前，将该权威事件交给动画控制器执行无动画语义收尾。这样另一真人即使不播放吃碰事件，也会移除已经被消费的出现牌。

对于 `selfAcked` 的 `await-response` 出现牌事件，继续使用现有恢复逻辑确保待响应牌可见，不得误清。该决策保留服务端定向动画屏障带来的性能和节奏优势。

备选方案是服务端让所有在线真人都成为吃碰事件的必需回执者。虽然也能触发正常播放清理，但会扩大同步屏障、增加等待与超时风险，并掩盖客户端跳播缺少语义收尾的问题，因此不采用。

### 3. 跳播、重复与快照恢复采用同一幂等收尾规则

`playback-mode-skip`、`already-played` 和 `selfAcked` 等路径在完成事件记账或回执前应用事件收尾。重复调用必须安全，不能移除属于更新响应窗口的另一张 held 牌。

当快照没有当前事件时，不因“事件为空”直接无条件删除 held 牌；客户端应结合权威状态判断是否仍存在同 card id 的活动响应牌。只有结果状态、权威状态不再包含该活动出现牌，或收到明确消费/归位事件时才清理。这避免网络回执刚完成但响应窗口仍有效时闪烁或提前消失。

### 4. 所有结果类型统一清理状态动画

状态动画控制器在进入任意结果状态时清理活动动画牌与 retained 视觉，而不是只识别 `result.type=win`。`hu` 的动作效果仍由事件动画负责；进圈、流局与结算进入稳定结果画面后不得保留上一响应牌。

## Risks / Trade-offs

- [风险] 对跳播事件直接释放可能误删随后出现的新牌 → 对带牌事件核对 card id，并依据单调 `eventSeq` 与权威活动出现牌状态执行幂等收尾。
- [风险] 将 `pass` 误判为响应结束导致其他玩家看不到待响应牌 → 明确把 `pass` 归为保留事件，只有最终 `unclaimed`、消费动作或结果事件释放。
- [风险] 状态控制器和事件控制器同时清理产生重复调用 → 释放接口必须幂等，重复清理不得报错或影响后续视觉。
- [风险] 只修复已知入口仍遗漏事件缺口恢复 → 回归测试同时覆盖正常播放、`selfAcked`、跳播、重复事件、无当前事件快照及终局状态。

## Migration Plan

1. 先补充动画控制器和在线控制器的失败回归用例，固定两个已确认路径。
2. 实现统一语义收尾并接入正常播放、跳播及 `selfAcked` 分支。
3. 扩展状态结果清场并运行动画、在线同步、服务端核心及后端回归。
4. 上传微信小游戏测试版本，在两真人两 AI 真机房间复测“真人 A 出牌、真人 B 吃牌后再出牌”和进圈/流局场景。

回滚时可整体回退客户端收尾调用与测试；本变更没有数据迁移、服务端协议变更或持久化兼容要求。
