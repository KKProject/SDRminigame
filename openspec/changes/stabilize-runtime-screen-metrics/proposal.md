## Why

微信小游戏真机横屏启动时，运行时偶尔会短暂返回未稳定的窗口宽高或安全区信息。当前项目只在模块加载时读取一次尺寸并创建固定布局，导致背景能够铺满实际 Canvas，但头像、手牌、弃牌区等元素仍按错误的小尺寸计算，全部挤在局部区域。

## What Changes

- 将窗口尺寸、像素比和安全区从启动期不可变常量改为可更新的运行时渲染指标。
- 启动时校验屏幕指标是否有效且符合横屏游戏预期；遇到临时异常指标时暂缓创建正式牌桌布局，并在后续帧重新读取。
- 监听微信窗口尺寸变化，在真实尺寸稳定后原子更新 Canvas backing store、2D context 缩放、安全区和牌桌布局。
- 尺寸变化时重建依赖坐标的布局和动画目标，清理或安全恢复基于旧尺寸的临时动画，避免新旧坐标混用。
- 背景继续覆盖完整 Canvas；其他 UI 元素始终使用最新稳定的逻辑尺寸与安全内容区域。
- 增加启动时错误尺寸、竖横屏尺寸切换、重复相同尺寸通知和安全区变化的自动检查。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `huapai-table-interaction`: 强化响应式牌桌布局要求，增加运行时尺寸稳定确认、异常启动尺寸恢复和窗口变化后重新布局的行为。
- `client-animation-system`: 增加布局尺寸变化期间动画目标失效、清理与恢复要求，避免动画继续使用旧屏幕坐标。

## Impact

- 影响 `js/render.js` 中窗口信息读取、Canvas 尺寸与 context 缩放管理。
- 影响 `js/main.js` 的启动、帧循环和窗口变化监听生命周期。
- 影响 `TableLayout`、`TableRenderer` 和动画控制器的尺寸更新、布局重建与旧动画清理。
- 影响菜单和牌桌输入命中区域，使其随最新稳定布局同步更新。
- 不改变背景资源、牌局规则、在线协议或服务端状态。
