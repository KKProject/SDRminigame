## Why

当前规则里“玩家打过某张牌后不能再吃/胡该牌”的表述依赖宽泛的 discard history，容易把摸牌后直接流走、系统弃牌、动画弃牌等非手牌行为误算进去。实际牌桌规则要求只有开局发到手牌中的牌，被玩家主动从手牌里打出，才会形成后续禁吃禁胡和进圈赔三家的依据。

这次变更要把“打过记录”的来源、禁吃禁胡范围、以及强制吃牌冲突时的处罚写成明确规则，避免服务端裁决、客户端提示和后续测试口径不一致。

## What Changes

- 明确“打过某 key”只统计玩家从开局手牌集合中主动选择打掉的牌。
- 明确后续从牌堆抓出的牌不进入手牌，抓牌后无人响应直接流走或被系统弃掉，不产生“打过记录”。
- 将禁胡从原来的“chi-style hu”扩展为：玩家曾从开局手牌主动打过某 key 后，本轮后续不能用同 key appearing card 胡牌，不论该牌在最终门型里组成 `xy`、`xyz`、`xx`、`xxx` 或高阶同张门。
- 保留并收紧禁吃：玩家曾从开局手牌主动打过某 key 后，本轮后续不能吃同 key appearing card。
- 新增强制吃牌冲突规则：如果某 key 是玩家必须吃的牌，但该玩家本轮已经从开局手牌主动打过该 key，则该玩家进圈，其他三家获赔。
- 明确被别人拿走的已打出手牌仍然保留在原玩家的“打过记录”中。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `huapai-game-rules`: 收紧“打过记录”的来源，并完善基于开局手牌主动打出记录的禁吃、禁胡、强制吃冲突进圈规则。

## Impact

- 服务端规则裁决：需要区分“开局手牌主动打出”与抓牌流走/系统弃牌记录。
- 客户端可操作按钮：需要与服务端一致，不向被禁吃/禁胡的玩家展示不可执行响应。
- 回放/快照/日志语义：需要保留足够信息区分手牌主动出牌和非手牌流转。
- 测试：需要覆盖摸牌不污染打过记录、手牌主动打出后禁吃禁胡、以及必须吃但已打过导致进圈赔三家的场景。
