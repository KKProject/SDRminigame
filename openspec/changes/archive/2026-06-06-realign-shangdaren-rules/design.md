## Context

本次变更以 `/Users/gaohaibo/Desktop/sdr_rules.md` 的《上大人棋牌规则｜开发实现版 v1.0》为实现基准。现有 spec 已经有上大人牌组、开局、吃碰招踏、八门胡、计福、AI 和桌面交互能力，但部分行为仍沿用早期理解：摸牌与手牌关系、响应顺序、特殊搭子强制操作、招/踏对子校验、出牌限制、三家赔付和两类流局的庄家变化都需要统一。

规则引擎应继续作为 AI、UI 和计分的单一事实来源。UI 只展示规则引擎给出的状态与合法动作，AI 只在合法动作集合内决策，计分只消费胡牌拆门与公开操作牌组摘要。

## Goals / Non-Goals

**Goals:**

- 将回合状态机改为“出现牌驱动”：摸牌或打牌产生出现牌，按 `胡 > 踏 > 招 > 碰 > 吃` 和逆时针响应顺序解析。
- 明确开局、滑庄、接庄、将牌、接庄三次凑牌听牌检查、两类流局和庄家变化。
- 统一吃、碰、招、踏、特殊搭子、碰吃冲突、出牌限制、进圈判定与胡牌搜索规则。
- 统一福数、胡牌等级、胡牌三家赔付、进圈赔付和当前局公开操作福数展示。
- 让 AI 与玩家提示严格依赖规则引擎的合法动作和违规原因。

**Non-Goals:**

- 不新增牌面美术、音效或网络对战能力。
- 不改变四人座位布局、横屏背景优先桌面或现有手牌列布局原则。
- 不引入随机 AI 风格；本次 AI 仍以确定性合法策略为主。

## Decisions

1. 使用统一的 `AppearingCard` 流程对象表示摸牌和打牌产生的出现牌。

   该对象记录来源座位、来源类型、响应起点、是否允许出牌者自响应、原始牌 id、当前动画/弃牌归属。这样摸牌不入手、打牌等待响应、无人响应后进入弃牌区、响应链结束后下家摸牌都能走同一套状态机。

   备选方案是保留 draw/discard 两条流程分支，但强制吃碰、截胡、踏牌来源和无人响应推进会重复实现，容易出现优先级不一致。

2. 合法动作评估分两层：先按全局操作优先级与座位顺序选出最高可处理层级，再在同一玩家同一层级内提供选择。

   胡牌永远先于普通凑牌。同一张出现牌多人可胡时只取响应顺序第一个人。同一玩家在不违反优先级时可在多个普通动作之间选择，例如碰吃冲突中的吃或碰。强制特殊搭子会把对应动作标为 mandatory，除非更高优先级动作已经截走该牌。

3. 高阶牌组对子校验采用“即时证明，非永久锁定”。

   招/踏发生时立即计算当前可用对子证明，胡牌时重新校验最终拆门。对子证明不永久占用手牌，后续出牌或被碰不追溯早前合法性；只有再次招/踏或胡牌时重新计算。这与规则文档的维护建议一致，也能减少状态污染。

4. 胡牌搜索输出可审计的拆门结果。

   胡牌检测必须返回 8 门、唯一 `xy`、高阶牌组对子摘要、自然刻子/碰牌/招/踏来源和最终计福条目。计分与结果弹窗不再反推牌型，避免 UI 与规则引擎各算一遍。

5. 出牌合法性由规则引擎裁决，AI 和 UI 只消费合法候选。

   规则引擎需要识别完整原句保护、多余牌可拆、四张/五张拆打上限、接庄/庄家刻子要求以及“无牌可打且未胡”的进圈。真人非法点击保持状态不变并提示；AI 若无合法候选则按规则进入进圈结果。

## Risks / Trade-offs

- 规则组合复杂导致胡牌搜索性能下降 -> 使用按句子分组、牌数计数和 memoization，只在出现牌候选态、听牌检查和胡牌结算时执行完整搜索。
- 旧 UI 可能假设摸牌直接进入手牌 -> 在状态层保留出现牌展示字段，手牌只在吃/碰/招/踏/胡等合法动作解析后变化。
- 新旧计福口径可能影响现有测试期望 -> 将自然刻子、碰牌、原句、招踏增量、将牌倍率拆成独立单元测试，并更新旧测试夹具。
- 强制特殊搭子和放弃吃惩罚容易误判 -> 将“同一句话 + 同一缺失牌”作为持久 penalty key，并在动作历史中记录首次放弃与后续吃牌。
- 接庄三次凑牌听牌检查依赖听牌算法 -> 先实现可复用 `isListening`，再接入接庄限制、庄家刻子要求和 UI 提示。

## Migration Plan

1. 补齐规则模型与测试夹具：牌组、句子位置颜色、出现牌、门型、挂对子证明、动作历史、进圈原因、庄家流转。
2. 替换开局和回合状态机，使所有摸牌/打牌都进入统一出现牌响应流程。
3. 迁移吃碰招踏、强制操作、出牌限制、胡牌/听牌检测和进圈判定。
4. 迁移计分与结算，确保公开操作福数和最终胡牌福数使用同一条计算路径。
5. 更新 AI 与 UI，让它们只消费规则引擎输出的合法动作、强制标记、警告和结果。
6. 以规则文档最小测试清单为回归基线，覆盖核心 T001-T040 场景。

回滚策略：保留变更前的测试夹具和入口接口形状，若新状态机无法一次切换，可用配置短期回退到旧规则引擎；但归档前默认规则必须指向新版规则。
