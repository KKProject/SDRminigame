## MODIFIED Requirements

### Requirement: 并发响应窗口裁决
服务端权威状态机 SHALL 为存在响应机会的出现牌创建并发响应窗口。响应窗口 MUST 记录每个可响应席位的合法动作、响应状态和选择结果；服务端 MUST 只接受窗口内对应席位提交的合法响应意图，并 MUST 在当前最佳选择无法被未决候选推翻时立即裁决。裁决后，服务端 MUST 清空响应窗口、使其他未决响应失效，并应用唯一胜出的胡、吃、碰、招或踏动作；若所有席位均过牌或无可用选择，服务端 MUST 将出现牌按无人响应处理。服务端构建公共状态时 MUST 只下发不泄露具体候选动作的响应窗口摘要；具体响应按钮、胡牌候选和动作参数 MUST 仅通过本人私密视图或私密补丁下发。

#### Scenario: 多个真人同时响应
- **WHEN** 同一张出现牌可被多个真人席位响应
- **THEN** 服务端 MUST 在同一个响应窗口内向每个真人开放其本人合法响应
- **AND** 任一真人的响应选择 MUST NOT 依赖更早响应顺序真人先提交过牌

#### Scenario: 当前最佳选择提前裁决
- **WHEN** 服务端收到一个合法响应选择
- **AND** 所有未决候选动作都无法按优先级和响应顺序击败该选择
- **THEN** 服务端 MUST 立即裁决该选择为胜出动作
- **AND** 服务端 MUST 取消同一响应窗口内其他未决动作

#### Scenario: 高优先级选择清空低优先级私密动作
- **WHEN** 响应窗口中某玩家已提交当前最佳选择
- **AND** 另一个未决玩家的全部候选动作都无法击败该选择
- **THEN** 服务端 MUST 在该未决玩家的私密视图中清空响应按钮
- **AND** 该未决玩家后续提交同一窗口动作时 MUST 被拒绝为动作已失效

#### Scenario: 仍可击败当前最佳选择的玩家继续可操作
- **WHEN** 响应窗口中已经存在当前最佳选择
- **AND** 某个未决玩家至少存在一个候选动作可以按优先级或响应顺序击败该选择
- **THEN** 服务端 MUST 继续在该玩家的私密视图中下发合法响应按钮
- **AND** 服务端 MUST 等待该玩家选择、过牌、托管或超时后再裁决当前最佳选择

#### Scenario: 所有人过牌
- **WHEN** 响应窗口内所有候选席位均选择过牌、被托管过牌或因规则结果失去响应资格
- **THEN** 服务端 MUST 按无人响应处理当前出现牌
- **AND** 服务端 MUST 只生成最终归位事件，不为每个过牌生成公开动作事件

#### Scenario: 过期响应被拒绝
- **WHEN** 响应窗口已经裁决或版本已经更新后，客户端提交旧窗口的响应意图
- **THEN** 服务端 MUST 拒绝该意图且不改变权威状态
- **AND** 服务端 MUST 返回足以让客户端同步最新快照的错误信息

#### Scenario: 响应窗口期间正确构建公共状态
- **WHEN** 服务端构建存在响应窗口的公共状态
- **THEN** 公共状态 MUST 包含响应窗口 id、来源席位、来源类型、出现牌 id、候选席位、等待席位、已决策席位和仍阻塞裁决的席位摘要
- **AND** 公共状态 MUST NOT 包含其他玩家具体响应按钮、胡牌候选、手牌推导结果或动作参数
- **AND** 真人玩家 MUST 只能从本人私密视图或私密补丁获取自己的响应选项

## ADDED Requirements

### Requirement: 出现牌事务流程
服务端权威状态机 SHALL 将出牌和抓牌统一作为出现牌事务处理。每个出现牌公开事件 MUST 明确 `source`、`sourceSeat`、`card` 和 `appearanceResolution`；`appearanceResolution` 为 `await-response` 时，服务端 MUST 在出现牌动画回执完成后开启响应窗口；`appearanceResolution` 为 `auto-discard` 时，服务端 MUST 在同一公开事件中提交最终弃牌状态，并在自动归位动画回执完成后继续后续牌局推进。

#### Scenario: 出牌后存在响应机会
- **WHEN** 玩家打出一张可被至少一个席位响应的牌
- **THEN** 服务端 MUST 生成 `type=discard` 且 `appearanceResolution=await-response` 的公开事件
- **AND** 服务端 MUST 在该公开事件动画屏障解除后创建响应窗口

#### Scenario: 出牌后无人响应
- **WHEN** 玩家打出一张没有任何合法响应动作的牌
- **THEN** 服务端 MUST 生成 `type=discard` 且 `appearanceResolution=auto-discard` 的公开事件
- **AND** 服务端 MUST 在权威状态中提交该牌的最终弃牌位置
- **AND** 服务端 MUST NOT 再为同一次初始无人响应生成额外 `unclaimed` 事件

#### Scenario: 抓牌后存在响应机会
- **WHEN** 玩家从牌堆摸出一张可被当前规则响应的牌
- **THEN** 服务端 MUST 生成 `type=draw` 且 `appearanceResolution=await-response` 的公开事件
- **AND** 服务端 MUST 在该公开事件动画屏障解除后创建响应窗口

#### Scenario: 抓牌后无人响应
- **WHEN** 玩家摸出的牌没有任何合法响应动作
- **THEN** 服务端 MUST 生成 `type=draw` 且 `appearanceResolution=auto-discard` 的公开事件
- **AND** 服务端 MUST 在权威状态中提交该牌的最终弃牌位置
- **AND** 服务端 MUST 在自动归位动画屏障解除后继续下一家抓牌流程

### Requirement: 响应窗口关闭结果事件
服务端权威状态机 SHALL 在响应窗口关闭时根据裁决结果生成唯一的后续公开事件。若窗口以胜出动作关闭，服务端 MUST 生成对应的胡、吃、碰、招或踏公开事件；若窗口以所有候选均过牌或托管过牌关闭，服务端 MUST 生成 `unclaimed` 公开事件将保留出现牌归入弃牌区。响应窗口关闭后的公开事件 MUST 负责释放或消耗当前保留出现牌。

#### Scenario: 响应动作胜出
- **WHEN** 响应窗口裁决某个胡、吃、碰、招或踏动作为胜出动作
- **THEN** 服务端 MUST 清空响应窗口并应用该动作到权威状态
- **AND** 服务端 MUST 发布对应动作的公开事件
- **AND** 服务端 MUST 在该公开事件动画屏障解除后进入出牌、摸牌或结算等下一阶段

#### Scenario: 响应窗口无人最终响应
- **WHEN** 响应窗口中所有候选玩家均过牌、托管过牌或被提前淘汰
- **THEN** 服务端 MUST 清空响应窗口并发布 `unclaimed` 公开事件
- **AND** `unclaimed` 公开事件 MUST 包含来源席位、牌和最终弃牌位置
- **AND** 服务端 MUST 在该公开事件动画屏障解除后继续下一家抓牌流程

#### Scenario: 窗口关闭后状态一致
- **WHEN** 响应窗口已经关闭
- **THEN** 服务端公共状态 MUST 不再标记该响应窗口为 active
- **AND** 所有玩家私密视图 MUST 不再包含该窗口的响应按钮
