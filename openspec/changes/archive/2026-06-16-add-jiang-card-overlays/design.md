## Context

当前牌局在开局发牌后已经通过权威状态确定 `jiangCard` / `jiangPhraseId`，规则上同一句话的三个字都属于将牌。现有界面主要通过局部文字或区域提示表达将牌信息，无法在手牌、弃牌区、凑牌区和动画过程中直接标识每一张将牌。

渲染层已有统一 `drawCard()` 入口，并且近期已经接入出现牌来源覆盖图，具备按 atlas 源尺寸比例叠加覆盖图的基础能力。本次改动应复用这条统一绘制链路，把“是否将牌”和“使用哪种将牌覆盖图”的判断集中处理，减少各个绘制调用点遗漏的风险。

## Goals / Non-Goals

**Goals:**

- 在整个牌局中，只要 `jiangPhraseId` 已确定，所有正面可见且属于该将牌句子的牌都叠加将牌图片覆盖。
- 大牌、小牌、mini 牌分别使用 `icon_jiang_big`、`icon_jiang_small`、`icon_jian_mini_hr`。
- `icon_jian_mini_hr` 按 atlas 语义左旋 90 度后绘制。
- 覆盖图按 atlas JSON 中覆盖图源尺寸与基础牌面源尺寸的比例同比缩放，并以牌面中心居中。
- 将牌覆盖与已有出现牌来源覆盖图兼容，出现牌既能显示来源覆盖，也能显示将牌覆盖。

**Non-Goals:**

- 不改变将牌判定规则、发牌流程、计福规则或服务端状态字段。
- 不改变现有牌面 atlas 的基础牌图匹配逻辑。
- 不为背面牌或不可见对手手牌显示将牌信息。

## Decisions

1. **将牌判断集中在渲染器状态上下文中完成**

   渲染器在每次绘制牌局时记录当前 `jiangPhraseId`，`drawCard()` 根据牌的 `phraseId` 与当前将牌句子比较，自动决定是否叠加将牌覆盖图。这样手牌、弃牌、凑牌、出现牌和动画牌只要走统一绘制入口，就能得到一致表现。

   备选方案是在每个调用点传入 `jiangOverlay` 选项；该方案更显式，但调用点多且容易漏掉动画或兜底路径。

2. **覆盖图资源通过语义映射获取**

   在 `AssetLoader` 中提供将牌覆盖图语义映射：`big` → `icon_jiang_big`，`small` → `icon_jiang_small`，`mini` → `icon_jian_mini_hr`。渲染层只按牌面尺寸请求覆盖图，不直接散落 atlas frame 名称。

   备选方案是渲染层直接调用 `getAtlasSprite(frameName)`；该方案实现快，但资源命名和旋转规则会泄漏到绘制逻辑。

3. **复用通用覆盖图 bounds 计算**

   将现有按源尺寸比例计算覆盖图边界的逻辑抽成可复用方法，用于出现牌来源覆盖图和将牌覆盖图。基础牌面源尺寸优先来自基础牌 sprite；当 fallback 文本牌或测试 stub 没有 sprite 时，使用对应尺寸的标准源尺寸兜底。

4. **叠加顺序为基础牌面 → 出现牌来源覆盖图 → 将牌覆盖图**

   出现牌来源覆盖图表达“这张牌从哪里来”，将牌覆盖图表达“这张牌是不是将牌”。将牌标识需要在最终视觉上清楚可见，因此放在来源覆盖图之后绘制。

## Risks / Trade-offs

- [Risk] 当前 atlas 中可能尚未包含 `icon_jiang_big` 或 `icon_jian_mini_hr` 精确 frame 名 → 实现阶段需要先校验资源名；缺失时应补齐 atlas 或建立明确映射，不能静默使用错误图片。
- [Risk] 将牌覆盖图如果在每个调用点单独处理，容易遗漏动画或隐藏/交接路径 → 通过统一 `drawCard()` 接入，并补充自检覆盖静态、动画、出现牌和 mini 牌路径。
- [Risk] mini 覆盖图需要旋转，旋转后尺寸参与同比缩放容易出错 → 统一使用 sprite 旋转后的逻辑源尺寸计算，并用测试断言绘制目标尺寸与旋转方向。
- [Risk] fallback 文本牌没有基础 atlas 源尺寸 → 使用尺寸级别标准源尺寸兜底，保证覆盖图仍能显示且不会阻断绘制。
