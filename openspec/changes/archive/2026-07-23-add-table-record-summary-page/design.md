## Context

最终局已经通过 `viewRecord` 动作暴露“查看战绩”入口，但 `OnlineController.handleActionTap` 目前只写入“战绩功能待开放”反馈。服务端房间文档已有累计 `tableScores`、玩家资料、房间配置和最终局号，却没有胜局累计；客户端现有 `roundResult` 页面只表达单局牌况，不适合直接承担整桌排名。

设计稿以四行排名榜呈现当前房间总结算。项目采用单 Canvas 渲染和服务端权威房间状态，因此需要同时补齐房间统计、脱敏公共状态、客户端视图状态、响应式布局与角色化操作。

## Goals / Non-Goals

**Goals:**

- 在最终局“查看战绩”后展示与设计稿一致的当前房间总结算页。
- 由服务端权威累计总分、胜局和实际完成局数，并保证重复持久化不会重复计数。
- 保持四名玩家排名、头像、昵称、胜局、总积分、房号和玩法信息可读。
- 复用现有 `tableResult` 退出与重开状态机，按玩家角色展示可用操作。
- 公共状态不得泄漏 `openid` 或其他私密身份数据。

**Non-Goals:**

- 不实现大厅入口、跨房间历史列表、分页查询或长期战绩档案。
- 不新增金币、货币余额或奖励结算。
- 不新增公开数字玩家 ID。
- 不改变上大人计分规则或最终房间重开规则。

## Decisions

1. **房间内维护幂等累计统计。** 在权威 room 中保存按 seat 索引的 `tableStats`，至少包含 `winRounds`；现有 `tableScores` 继续作为累计积分唯一来源。每局结果使用与局号和结果身份绑定的 applied key，确保重复 snapshot、生命周期同步或服务重启不会重复增加胜局。

2. **只把脱敏总结算模型放入公共状态。** 当房间达到 `tableResult` 时构造 `tableRecord`，包含 `roomId`、`completedRounds`、规范化 settings、按 seat 的昵称/头像/胜局/总分，以及当前重开摘要。模型不包含 `openid`；客户端座位旋转时与其他 seat 数据采用相同映射规则。

3. **排名采用确定性全序。** 玩家先按总积分降序，再按胜局降序，最后按权威 seat 升序排序，并依次编号 1–4。只有排序第一名显示赢家徽章；即使多人同分也保持稳定、唯一的展示顺序，避免不同客户端产生不同排名。

4. **总结算是结果页之上的独立客户端视图。** 点击 `viewRecord` 设置本地 `tableRecordOpen`，不修改权威游戏 phase。布局和 renderer 增加独立总结算分支；这样返回/退出/重开状态变化仍由当前在线控制器和 `tableResult` 权威状态驱动。

5. **使用现有美术语言进行 Canvas 实现。** 首版复用大厅背景、远程头像、金红配色及 Canvas 图形/文字绘制，不要求把整张设计稿当作背景位图。后续如增加切图，只替换装饰层，不改变数据布局与命中区域。

6. **操作按钮由权威重开状态派生。** 所有玩家可退出；房主在决策窗口内可发起“再来一局”；非房主在未发起时显示不可点击的“等待房主”；发起后未确认真人显示“同意/拒绝”，已确认真人显示等待状态。客户端不得仅依据本地角色猜测房间已重开。

7. **设计字段映射到现有领域。** “金币变化”改为“总积分变化”；玩家 ID 省略；房间玩法由 `maxRounds`、`repeatRound`、`washTwice` 和 `payType` 组合为短文案。

## Risks / Trade-offs

- [旧 `tableResult` 房间没有 `tableStats`] → 读取时补零并使用当前最终结果做一次幂等归并，保证向后兼容。
- [同分排名是否应并列存在产品歧义] → 首版采用稳定 1–4 全序，与设计稿四个名次一致，并在规范中固定比较规则。
- [远程头像加载失败] → 使用昵称首字 Canvas 占位，与现有结果页行为一致。
- [窄屏四行信息拥挤] → 以 1560×878 设计坐标为基准等比适配 safe area，缩短玩法文案和昵称，四行保持同屏。
- [重开状态在页面打开后变化] → 页面每帧从最新权威 `tableRecord/rematch` 派生按钮，而不是缓存打开时状态。

## Migration Plan

1. 扩展房间初始化、结算归并和持久化，使旧字段缺失时安全补零。
2. 在 `tableResult` 公共状态和增量中加入脱敏 `tableRecord`。
3. 实现客户端座位映射、页面状态、布局、渲染与触摸操作。
4. 扩展服务端、在线同步、布局和 renderer 回归。
5. 部署后验证双真人与 AI 补位房间的最终局、退出和重开流程；回滚时客户端会回到原结果页，新增房间字段可被旧代码忽略。

## Open Questions

无。本 change 固定为当前房间总结算；跨房间历史战绩需要独立的数据保留与查询设计。
