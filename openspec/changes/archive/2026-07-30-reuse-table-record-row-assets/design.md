## Context

- 对局结果页（`drawRoundResultPage`，`js/game/renderer.js`）的玩家条目背景目前是纯 Canvas 自绘：`roundRect` + 三态半透明填充（本家金色 / 赢家淡红 / 其余米白）+ 描边。
- 总结算页（`drawTableRecordPage`）的条目已使用设计切图：赢家 `tableRecordFirstRow`（金色，1032×160）、其余 `tableRecordRow`（米色，1032×156），整图 `drawImage` 绘制，行高按图片原比例从行宽推导，因此无变形。
- 两张切图右侧约 `78%` 处自带一条竖分隔线，总结算页布局用 `scoreX = row.width * 0.78` 与之对齐。
- 对局结果页的行高由 `createRoundResultLayout` 独立 clamp（`92~132px`），行宽随屏幕变化，实际长宽比在约 `5.3~7.9` 之间浮动，与切图原比例 `6.6` 不一致，整图拉伸会压扁四角纹饰。
- 页面内已有九宫格工具 `drawNineSliceImage`（同页白板面板已在用），以及"切图优先 + Canvas 回退"的既有模式。
- 约束：不新增图片资源（延续包体积优化方向），页面为横屏专用。

## Goals / Non-Goals

**Goals:**
- 对局结果页条目背景复用总结算页两张条目切图，统一两个页面的条目视觉。
- 切图在任意行比例下不产生明显变形（四角纹饰、边框粗细保持）。
- 切图内自带的竖分隔线与行内数据列自然对齐，不出现"错位装饰线"。
- 金色语义两页统一：金色行 = 赢家/第一名；本家仍可被清晰辨识。
- 切图缺失时行为不劣化：回退到现有自绘样式，页面功能不受影响。

**Non-Goals:**
- 不改动总结算页的任何绘制与布局。
- 不新增或替换图片资源，不改资源清单结构（复用已注册的 `tableRecordRow` / `tableRecordFirstRow` 语义键）。
- 不调整条目内头像、昵称、牌型、胡数、分数等既有内容的绘制逻辑（仅 stats 列起点因分隔线对齐而移动）。
- 不处理竖屏或非全屏场景。

## Decisions

### 1. 行背景用九宫格绘制，而非整图拉伸或按图片比例推导行高

- **选择**：`drawNineSliceImage` 绘制两张条目切图，源边距参考白板面板的用法取固定值（约 `30px`，小于图片高度的一半），目标边距按行高比例 clamp。
- **理由**：对局结果页行高必须保持独立 clamp（行内要容纳手牌立柱，有最小高度需求），无法像总结算页那样按图片原比例推导行高；整图拉伸在 `7.9:1` 的行上会把切图垂直方向压到约 `84%`，四角纹饰明显变形。九宫格保四角、只拉伸边缘和中心，且该页白板已有同模式先例。
- **备选**：
  - 整图拉伸：实现最简，但纹饰变形，放弃。
  - 按图片比例推导行高：与现有行高 clamp 及手牌显示需求冲突，放弃。
  - `drawHorizontalThreeSliceImage` 三切片：只保横向，纵向仍会压缩边框，不如九宫格，放弃。

### 2. stats 列起点对齐切图分隔线（行宽 `78%`）

- **选择**：`createRoundResultLayout` 中 `stats.x` 从"右侧固定 `126~210px`"改为对齐行宽 `78%`（即 `statsWidth = rowWidth - round(rowWidth * 0.78)`），胡数/分数继续平分 stats 区。
- **理由**：切图分隔线是烙在图里的，位置约 `78%`（九宫格拉伸下实际落点约 `77~78%`，偏差 ≤1% 行宽，视觉不可察）。对齐后分隔线自然成为"牌型区 | 数据区"分界。典型行宽约 `730px` 时 statsWidth ≈ `160px`，落在原 clamp 区间（`126~210`）内，数据区反而更宽松，牌型区仅收窄约 `35px`。
- **备选**：
  - 不动布局，任由分隔线落在牌型区中间：视觉错位，放弃。
  - 让设计出无分隔线变体图：增加包体积，与优化方向相悖，放弃。

### 3. 金色行给赢家，本家仅靠角色标签辨识

- **选择**：赢家行用 `tableRecordFirstRow`（金色），其余（含本家非赢家时）用 `tableRecordRow`（米色）；切图之上不叠加任何自绘底色或边框，本家辨识由"本家"角色标签与头像描边色差承担。同步修订既有规格中"本家高亮行"的表述为"本家标签标识"。
- **理由**：总结算页金色 = 第一名，两页语义必须一致，否则玩家对照两页时困惑。切图自带完整装饰边框，叠加自绘描边在实机检视中被确认为视觉噪音。赢家此外还有胡牌装饰（`drawRoundResultWinnerDecoration`）双重标识。
- **备选**：
  - 金色给本家——保留现状语义但与总结算页冲突，放弃。
  - 本家行叠加金色描边高亮——初版实现方案，实机检视后确认与切图边框叠加显得多余，移除。

### 4. 保留自绘回退，原三态填充作为 fallback

- **选择**：切图（含九宫格绘制成功判定）不可用时，走现有 `roundRect` 三态填充 + 描边逻辑，代码结构与总结算页 `rowImage ? drawImage : 自绘` 对称。
- **理由**：既有规格要求资源缺失不得阻塞结果页展示与交互；回退分支零新增成本。

### 5. 行距与圆角处理

- **选择**：保留现有行距（`rowGap ≥ 3px`）；切图绘制路径下不再画圆角矩形填充，圆角视觉由切图自身边框承担。
- **理由**：切图边缘自带描边收口，行距维持现值即可分隔相邻行；总结算页 `rowGap = 0` 是因其行高按图片比例推导、图内留白充足，对局结果页行高被压缩后仍保留小间距更稳妥，且避免布局二次改动。

## Risks / Trade-offs

- [九宫格拉伸使分隔线落点偏离 `78%`] → 偏差经推算 ≤1% 行宽（约 `5px`），且分隔线两侧内容均有内边距，视觉不可察；如实机观察明显，可微调对齐常量。
- [取消行级高亮后本家辨识度依赖标签] → "本家"/"本家·胡牌"红底标签与本家头像金描边已提供辨识；如实机反馈不足，可考虑小面积角标而非整行描边。
- [`first_row` 与 `row` 源图高度差 4px（金色带光晕）] → 九宫格按各自源尺寸切片，目标行高一致，光晕差异被吸收，无需特殊处理。
- [stats 区变宽约 `35px`，牌型区收窄] → 牌型列宽度为动态计算，收窄幅度 <5% 行宽；既有"mini 牌保持可辨认"规格由现有缩放逻辑保障，实机横屏最窄安全区需回归确认。
- [切图为不透明底，覆盖白板面板纹理] → 与总结算页表现一致，属预期视觉统一，非缺陷。
