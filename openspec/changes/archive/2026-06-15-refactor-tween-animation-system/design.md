## Context

客户端目前由 `js/main.js` 的 `requestAnimationFrame` 循环调用 `TableRenderer.render`。`TableRenderer` 同时承担布局、绘制、手写补间、动画阶段切换、在线事件播放、本地操作预演、完成回调和部分事件去重职责；`OnlineController` 再通过渲染器方法协调权威事件、音效和动画回执。该结构已经能工作，但动画状态散落、完成时机难以统一，继续增加动画容易产生重复播放、相互覆盖或回执过早。

本次变更引入 Tween.js，但微信小游戏仍只有一个由游戏主循环驱动的 Canvas 渲染过程。动画系统必须兼容单机状态变化、在线权威事件、本地操作预演、四座位布局和现有音效逻辑，并保持服务端公开事件与回执协议不变。

## Goals / Non-Goals

**Goals:**

- 使用 Tween.js 统一数值补间和缓动，移除渲染器内重复的时间与插值计算。
- 建立独立动画管理器，使动画编排、事件映射、网络协调和 Canvas 绘制解耦。
- 为串行、并行、停留、取消、预演确认和完成回调提供统一语义。
- 保持现有动画表现、在线事件去重、动画完成回执和本地预演无重复播放行为。
- 让动画方案和生命周期可通过单元测试验证。

**Non-Goals:**

- 不修改上大人规则、服务端动作裁决、公开事件结构或数据库结构。
- 不在本次重构中重新设计动画视觉效果、时长和音效素材。
- 不引入新的渲染引擎、场景图或 DOM 动画方案。
- 不让 Tween.js 自行启动第二套 `requestAnimationFrame` 循环。

## Decisions

### 1. 使用 Tween.js 的独立 `Group`，由现有主循环统一更新时间

动画管理器持有自己的 Tween.js `Group`，`js/main.js` 在每帧将 `requestAnimationFrame` 时间戳传给动画管理器，再执行 Canvas 绘制。Tween.js 只负责更新视觉对象的数值，不持有渲染上下文，也不自行调度帧。

选择此方案是因为它能够保留当前游戏主循环，方便暂停、清空和测试，并避免多个时间源造成动作叠加。备选方案是让每个动画自行使用时间和帧循环，但会延续当前难以统一完成时机的问题。

### 2. 动画层拆分为管理器、动画预设和视觉状态

新增独立动画模块，职责如下：

- `AnimationManager`：管理活动动画、队列、串行/并行编排、取消、完成通知，以及本地预演的确认或回滚。
- 动画预设：把 `draw`、`discard`、`chi`、`peng`、`zhao`、`ta`、`hu` 等游戏事件转换为声明式动画方案，是游戏事件与动画实现之间的唯一映射层。
- 视觉状态：保存当前需要绘制的牌、文字效果及其 `x`、`y`、`scale`、`alpha` 等属性，供渲染器只读绘制。
- 布局目标解析器：根据当前布局和座位解析动画起点、桌前停留点、弃牌区及凑牌区目标，不负责播放生命周期。

`AnimationManager` 不访问网络、云函数、牌局裁决或 Canvas；`TableRenderer` 不处理 `eventSeq`、回执、重试和 Tween 生命周期；`OnlineController` 不访问 Tween 实例或补间属性。

备选方案是在 `TableRenderer` 内简单替换手写 `lerp` 为 Tween.js。该方案虽然改动较小，但不能解决职责耦合和重复动画入口问题，因此不采用。

### 3. 以声明式动画方案表达顺序与并行关系

动画预设输出由步骤组成的方案，步骤至少支持：

- `tween`：对一个视觉对象执行补间；
- `wait`：在桌前保持可响应牌；
- `parallel`：同时执行多个补间或效果；
- `sequence`：依次执行多个步骤；
- `effect`：播放动作字样等视觉效果；
- `complete`：以一次性完成信号结束方案。

管理器将方案转换为 Tween.js Tween 和 Group 操作。所有完成回调必须恰好触发一次；取消后的旧回调不得影响新动画。

### 4. 在线权威事件、本地预演和单机动画共用播放接口

动画管理器提供统一入口：

- `playAuthoritative(event, context)` 播放在线权威事件并返回完成结果；
- `preview(action, context)` 立即播放本地操作预演；
- `confirmPreview(event, context)` 将匹配预演对账为权威事件，复用已播放进度而不重播；
- `cancelPreview(reason)` 在服务端拒绝或权威事件不匹配时取消并对齐权威状态；
- `playStateTransition(transition, context)` 供单机模式或兼容层播放状态变化动画；
- `update(time)`、`getVisualState()` 和 `clear(reason)` 管理每帧更新与恢复。

在线控制器仍负责权威事件序号、音效去重和回执；它只在管理器通知权威动画完成后发送回执。本地预演的完成不等同于权威动画完成，只有确认成功并达到权威事件要求的最终阶段后才能回执。

### 5. 使用分阶段迁移与兼容适配

先引入 Tween.js 和动画管理器，再迁移牌飞行动画、停留与归位流程，随后迁移动作效果、本地预演和在线播放，最后迁移单机状态推断并删除旧逻辑。迁移期间保留一层兼容适配，使未迁移动画仍可按现有方式执行，但同一事件只能由新旧路径之一播放。

这样可逐步验证行为一致性并控制回归范围。最终状态不保留第二套动画引擎。

## Risks / Trade-offs

- [Tween.js 在微信小游戏模块环境中加载方式不兼容或增加包体] → 在迁移前先完成最小运行验证，并固定可用版本与构建接入方式。
- [新旧动画迁移期重复播放] → 以事件签名和动画所有权标记保证同一事件只进入一个播放路径，并为重复事件增加测试。
- [取消或替换动画后旧完成回调仍触发] → 管理器使用播放令牌和一次性完成器，取消时清理对应 Tween Group 与回调。
- [本地预演与权威事件不匹配导致画面跳变] → 预演保存可回滚视觉状态；不匹配时先取消预演，再以权威快照和事件恢复。
- [布局在动画中变化导致目标位置过期] → 动画开始时保存稳定起终点；仅在明确需要跟随布局的方案中通过目标解析器重新计算。
- [抽象层增加初期代码量] → 限制公共接口和动画步骤类型，只抽取现有行为需要的能力。

## Migration Plan

1. 接入并固定 Tween.js 版本，验证微信开发者工具与真机可正常加载、更新和清理 Tween Group。
2. 新增动画视觉状态、目标解析器和 `AnimationManager`，接入唯一主循环时间戳，但暂不替换现有动画。
3. 将牌飞行、桌前停留、弃牌区和凑牌区移动迁移到声明式预设，并逐项对比现有行为。
4. 迁移动作效果、本地预演确认/取消、在线权威事件完成通知和音效触发协调。
5. 让单机状态变化通过统一播放接口执行，删除 `TableRenderer` 内旧补间、动画状态与完成判断。
6. 完成单元测试、单机回归、在线多客户端真机测试和动画回执验证后移除兼容适配。

若迁移阶段出现阻断问题，可按动画类型切回尚未删除的旧路径；完成最终删除后，回滚方式为回退本次变更提交，不修改服务端数据。

## Open Questions

- Tween.js 采用 npm 构建依赖还是将经过许可的发布文件纳入项目，需要根据当前微信小游戏构建链和包体测试结果确定。
- 动作按钮反馈等非牌局流程动画是否在本次迁移末期一起纳入管理器，以实施时的耦合程度和测试成本决定。
