## Context

当前客户端存在本地预演和权威事件对账逻辑。这个模式能降低主观延迟，但在吃、碰、招、踏这类带优先级裁决的响应动作中，预演可能最终未胜出。我们讨论后决定将凑牌动作改为“服务端权威广播统一驱动”，牺牲一点确认前即时感，换取状态和动画一致性。

## Goals / Non-Goals

**Goals:**

- 点击响应动作后不提前移除手牌、不完成凑牌动画。
- 使用同一条权威凑牌事件驱动所有客户端。
- 让动作本人根据权威事件执行本地手牌 remove。
- 其他玩家只根据公开事件精准回显动作、字和数量。

**Non-Goals:**

- 不改变服务端响应优先级和规则裁决。
- 不在本 change 中实现完整增量快照替代。
- 不在本 change 中引入 protobuf。

## Decisions

### 决策 1：pending intent 不改变权威镜像

本地点击只记录 `pendingIntent`、禁用按钮或显示等待，不修改 `databus.seats[0].hand`，不追加公开 meld，不提交动画回执。

### 决策 2：权威凑牌事件字段按动作最小化

- 碰：`action=peng` + `symbolCode`，数量固定 3。
- 吃：`action=chi` + `phraseCode`，可选带 `incomingSymbolCode` 辅助动画来源。
- 招：`action=zhao` + `symbolCode` + `count`，`count` 只用于招，取 4、5、6。
- 踏：`action=ta` + `symbolCode` + 目标组标识，若规则保证唯一可省略目标组。

### 决策 3：动作本人由 seat 判断并移除手牌

客户端收到事件后把服务端 `seat` 旋转为本地座位。如果本地座位为 0，则按动作语义从手牌移除：

- 碰：移除 2 张同字。
- 吃：移除该句中除出现牌以外的 2 张。
- 招：移除 `count - 1` 张同字。
- 踏：按规则判断是否需要移除手牌；若踏仅消耗当前出现牌则移除 0 张。

### 决策 4：拒绝或未胜出只清 pending

如果服务端返回拒绝，或收到其他座位胜出的权威事件，客户端清理本地 pending intent 和按钮等待态，不做手牌补偿。

## Risks / Trade-offs

- [点击后反馈变慢] → UI 立即进入等待态，并可播放轻量按钮反馈，但不播放最终凑牌动画。
- [本人手牌 remove 依赖事件语义] → 事件字段必须足够还原本人应移除哪些字，缺失时请求快照恢复。
- [踏目标不唯一] → 首版实现前确认规则；若不唯一，事件必须包含 `targetMeldId` 或 `meldIndex`。

## Migration Plan

1. 先禁用响应凑牌的确认前完整本地预演。
2. 服务端补齐权威凑牌事件短字段。
3. 客户端收到权威事件后统一执行本人 remove + 动画。
4. 删除旧本地预演对账分支或仅保留出牌等非响应动作使用。
