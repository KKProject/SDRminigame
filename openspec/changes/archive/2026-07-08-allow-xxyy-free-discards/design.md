## Context

同句出牌限制当前由 `canDiscardPreservingPhraseDoor` 统一判断：出牌后需要仍能在同句出牌上限内保留或到达 `xyz`、`xxx`、`yyy`、`zzz` 之一。此前已经为 `xxyyz` 增加过特殊规则，允许先打单张 `z` 后停止，但尚未覆盖开局双对 `xxyy`。

本次规则来自既有玩法讨论：发牌手牌中同一句为 `xxyy` 时，它可以作为特殊可拆打结构处理，玩家可以从该句继续打牌，甚至四张都打完。

## Goals / Non-Goals

**Goals:**

- 让服务端出牌裁决允许开局同句 `xxyy` 自由拆打。
- 同步客户端 evaluator，确保前端可选牌与服务端裁决一致。
- 保持既有 `xxyyz` 行为不变，尤其是“先打单张 `z` 后停止”的分支。
- 增加回归测试覆盖 `xxyy` 与 `xxyyz` 的边界差异。

**Non-Goals:**

- 不调整胡牌八门分解、吃碰招踏响应优先级或计分。
- 不改变“后期摸牌不进手牌”的既有流程。
- 不新增持久化字段或迁移历史房间数据。

## Decisions

### 决策 1：在同句出牌合法性 helper 中识别 `xxyy` 自由拆打链

`xxyy` 规则属于同句出牌限制的一部分，应放在 `canDiscardPreservingPhraseDoor` 附近，而不是在 UI 或操作入口做特殊放行。这样服务端、AI、客户端提示都能共享同一个规则语义。

实现上应基于当前手牌同句计数和已从该句主动打出的历史计数判断：如果原始开局同句结构为两种 key 各 2 张、第三种 key 为 0 张，则该句的后续出牌可继续放行，直到该句手牌归零。

### 决策 2：服务端与客户端保持同构

项目当前有服务端 `services/backend/src/game/core/evaluator.js` 与客户端 `js/game/evaluator.js` 两份同构规则代码。此次修改必须同步两侧，避免客户端显示不可打或服务端拒绝已显示的牌。

### 决策 3：测试同时覆盖正向与边界

正向测试覆盖 `xxyy` 可打 `x`、可打 `y`、连续打到剩余单张仍可继续打。边界测试保留 `xxyyz`：先打单张第三 key 后，后续同句继续出牌应仍被拒绝。

## Risks / Trade-offs

- [Risk] `xxyy` 与 `xxyyz` 都包含双对，容易误把 `xxyyz` 也变成自由拆打。  
  Mitigation：判断 `xxyy` 时要求原始同句总数为 4，且计数分布精确为 `0,2,2`。

- [Risk] 客户端和服务端规则漂移。  
  Mitigation：同步修改两份 evaluator，并在服务端核心测试与客户端自检中覆盖相同场景。

- [Risk] 历史记录来源混淆，把摸牌流走也算进 `xxyy` 原始结构。  
  Mitigation：沿用当前同句主动出牌历史计数，不引入摸牌自动流走记录；规则只根据手牌和主动出牌历史推导本轮同句拆打链。
