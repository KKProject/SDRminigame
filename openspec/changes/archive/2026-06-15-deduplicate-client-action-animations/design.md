## Context

当前在线动画存在四个可能发起者：本地操作预演、服务端权威事件、`StateAnimationController` 状态观察补偿以及 `TableRenderer.updateMeldEffects` 副露差异动画。它们使用不同动画 ID，因此动画管理器无法识别这些视觉过程属于同一次牌局动作。

例如玩家点击“吃”后，本地预演会先播放来牌飞行和动作文字；服务端确认后又会创建完整三牌凑牌动画；在部分快照时序下，状态观察器或副露差异检测还可能再次补动画。结果是动作发起者看到多次重复动画，而旁观者需要的权威动画又不能简单取消。

## Goals / Non-Goals

**Goals:**

- 每次在线动作在每个客户端最多播放一次完整动画。
- 动作发起者点击后立即播放完整本地动画，以动画遮盖网络延迟。
- 服务端确认动作时，发起者只进行对账和最终静态状态交接，不重播动画。
- 其他玩家仍通过服务端权威事件完整看到动作过程。
- 动作发起者仅在本地动画完成且服务端确认成功后回执。
- 正常在线流程不再由状态观察器和副露差异检测补播重复动画。

**Non-Goals:**

- 不改变服务端牌局裁决、动作优先级或牌局规则。
- 不移除动画屏障和动画完成回执机制。
- 不要求预测服务端可能拒绝的最终牌局状态；拒绝时仍以权威快照恢复。
- 不在本变更中重新设计单机动画表现。

## Decisions

### 1. 使用统一动作身份关联本地动画和权威事件

客户端为本地动作保存一个待确认记录，至少包含动作类型、来源牌、操作席位、本地动画状态和匹配后的 `eventSeq`。权威事件到达时按动作类型、发起席位和关键牌或副露信息匹配，而不是创建新的动画计划。

选择统一动作身份，是因为当前 `local-preview:*`、`online:*`、`state:*` 和 `chi-combo:*` ID 彼此独立，无法从动画管理器层面直接去重。

### 2. 动作发起者本地动画必须是完整动画

打牌本地动画必须完成出现牌的权威分支；吃、碰、招、踏本地动画必须播放完整牌组展示并进入凑牌区。权威事件到达后仅补充本地动画创建时未知的最终目标或分支，并继续尚未完成的部分，不得从头重播。

备选方案是本地只播放很短的点击反馈，等服务端确认后再完整播放。该方案会重新暴露网络等待感，因此不采用。

### 3. 使用双条件状态机控制发起者回执

发起者的待确认动作维护两个独立条件：

```text
localAnimationCompleted
authoritativeEventConfirmed
```

只有两个条件都为真时，客户端才调用一次 `finishAnimation(eventSeq)`。无论动画先完成还是网络先返回，结果一致。

### 4. 旁观者继续播放权威事件

当权威事件的 `actingSeat` 不是本地席位时，继续通过 `playOnlineEvent` 播放完整动画。该路径是旁观者了解牌局过程的唯一正常动画来源，并继续受 `eventSeq` 去重保护。

### 5. 限制补偿动画的职责

正常在线模式存在当前权威事件或本地待确认动作时：

- `StateAnimationController` 不得根据快照补播相同动作；
- `updateMeldEffects` 不得根据新增副露播放动作文字或组合牌动画；
- 渲染器只负责在动画过程中隐藏对应静态牌，并在结束后显示最终状态。

补偿路径仅在无可播放事件的恢复场景使用，并优先直接恢复静态状态。

### 6. 服务端拒绝触发权威恢复

服务端拒绝动作时取消待确认本地动画，清理临时视觉与声音状态，并使用返回或重新拉取的权威快照恢复。被取消动画的完成回调不得发送动画回执。

## Risks / Trade-offs

- [本地完整动画开始后服务端拒绝，玩家会短暂看到未成立动作] → 拒绝时立即取消并恢复权威状态，同时显示拒绝原因。
- [本地动作与权威事件匹配条件过宽会错误对账] → 使用动作类型、发起席位、关键牌 ID 和副露内容组成稳定动作身份。
- [匹配条件过严会让发起者退化为权威重播] → 对服务端补充字段采用兼容匹配，并增加各动作类型自动测试。
- [关闭正常补偿动画后可能暴露事件缺失] → 重连和事件缺口场景明确走权威静态恢复，不依赖正常动作动画补播。
- [动画先完成但网络较慢时画面短暂停在最终状态] → 保持最终临时视觉，等待权威确认后完成静态交接和回执。

## Migration Plan

1. 为在线控制器和动画控制器增加统一待确认动作状态与动作身份。
2. 将打牌、吃、碰、招、踏的本地预演升级为完整本地动画。
3. 调整权威事件消费：发起者对账，旁观者播放。
4. 将状态观察器和副露差异动画限制为恢复兜底。
5. 增加发起者、旁观者、网络先后顺序、拒绝和重复快照测试。

## Open Questions
