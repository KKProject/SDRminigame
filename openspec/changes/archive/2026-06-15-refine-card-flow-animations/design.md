## Context

当前在线牌局由服务端生成权威公开事件，客户端播放事件动画并回执，服务端在动画屏障解除后继续推进。抓牌、出牌、无人响应归位和凑牌目前分别播放，导致出现牌可能重复显示、短暂消失或与静态牌切换跳位；凑牌动画也只突出响应牌，无法完整表达最终组成的一手牌。

本次调整同时影响服务端事件语义、客户端 Tween.js 动画编排、布局目标解析、临时牌渲染和动画回执时机。牌局规则与操作优先级不变。

## Goals / Non-Goals

**Goals:**

- 将抓牌与出牌统一为可复用的“出现牌复合动画”，根据服务端已知的响应情况进入等待或自动归位分支。
- 让等待响应的大牌、动画牌和最终静态 mini 牌在任意时刻只显示一种，切换无闪烁、重叠和跳位。
- 将吃、碰、招、踏等凑牌动作以完整牌组作为一个动画整体展示。
- 保持服务端权威推进和动画屏障，明确等待视觉与动画完成回执并不是同一个生命周期。
- 让本地操作预演能够立即播放动画和音效，并与权威事件无重复地衔接。

**Non-Goals:**

- 不修改吃、碰、招、踏、胡、过的规则判定和优先级。
- 不修改手牌首次分列、弃牌区和凑牌区的静态排列规则。
- 不改变离线模式的牌局规则；离线模式仅复用相同动画编排。
- 不新增动画库，继续使用现有 Tween.js 动画层。

## Decisions

### 1. 使用统一的出现牌事件与公开动画分支

抓牌和出牌事件增加公开字段 `appearanceResolution`，取值为：

- `await-response`：事件创建时至少存在一个可响应操作。
- `auto-discard`：事件创建时服务端已经确定无人可响应，出现牌动画结束后直接归入弃牌区。

该字段只公开动画分支，不公开可响应玩家、动作类型或暗牌信息。客户端不得根据本地规则重新推断分支。

选择由服务端直接下发分支，是因为服务端已经完成规则计算，客户端推断既可能产生分歧，也可能泄露不应公开的操作信息。

### 2. 将“动画完成”和“等待牌仍显示”拆成两个生命周期

`await-response` 分支先播放出现牌的 `80% → 120% → 100%` 入场动画。入场动画完成后，动画管理器将该牌转为“保留出现牌”，大牌继续显示，同时客户端提交当前事件动画回执。服务端收到回执后开放响应窗口。

保留出现牌不是仍在运行的 Tween，也不继续占用当前事件动画屏障。后续“过”不会移除该牌；吃、碰、招、踏、胡等消耗出现牌的动作开始时立即移除。若所有响应者最终都选择“过”，服务端发布最终归位事件，将保留出现牌移动到弃牌区。

这样既满足玩家操作前能持续看到当前牌，也不会因为视觉停留而阻止服务端开放操作。

### 3. 已知无人响应时使用一次复合事件完成归位

当服务端在抓牌或出牌事件创建时已经确定无人可响应，服务端先提交该牌最终进入弃牌区的权威状态，再发布带 `auto-discard` 分支的出现牌事件。客户端在动画期间临时隐藏对应的静态 mini 牌：

1. 在出现位置播放 `80% → 120% → 100%`。
2. 从正常大牌大小缩小并移动到布局系统计算出的最终弃牌槽位。
3. 到达后移除动画牌，并显示已经存在于权威快照中的静态 mini 牌。
4. 完成整段复合动画后再提交一次事件回执。

服务端不再为这种“初始即无人响应”的情况额外发布 `unclaimed` 事件。若事件创建时存在响应机会、但后来所有人选择“过”，仍需发布最终归位事件，因为该结果无法在最初出现牌时确定。

### 4. 动画终点完全由静态布局结果驱动

动画控制器不自行估算弃牌和凑牌终点。布局层为事件提供目标矩形、最终尺寸和方向；动画最终帧直接使用该矩形。渲染器以稳定的 card id 或 meld id 隐藏对应静态结果，并只在动画到达后解除隐藏。

最终动画对象与静态对象共用相同位置和尺寸数据，可以避免最后一帧到静态显示之间的跳位。四个席位均使用同一套目标解析接口。

### 5. 凑牌动画使用完整牌组整体

吃、碰、招、踏等公开动作事件必须包含稳定的 meld id、动作类型、来源席位和最终公开牌组。客户端按手牌分列规则，用大图构建完整牌组动画模型，并以一个组容器驱动所有子牌：

1. 动作开始时立即移除被消耗的保留出现牌。
2. 在牌桌中央显示完整牌组，整体播放 `80% → 120% → 100%`。
3. 整体缩小并移动到目标玩家凑牌区的最终组位置。
4. 到达后移除动画组，并解除对最终静态 meld 的隐藏。

组内牌的相对位置在整段动画中保持不变，最终大小与凑牌区 mini 牌完全一致。使用组容器变换，可以避免每张牌独立 Tween 产生不同步。

### 6. 本地预演复用同一个动画状态机

本地玩家抓牌、出牌或执行凑牌动作时，可以立即开始对应动画与音效以遮盖网络延迟。收到权威事件后，动画控制器按操作标识和事件序号确认预演：

- 已播放的入场阶段不重播。
- 权威分支为 `await-response` 时，将当前大牌转为保留出现牌。
- 权威分支为 `auto-discard` 时，从当前动画进度继续归位阶段。
- 权威凑牌事件确认预演时，继续未完成阶段并只提交一次回执。
- 权威事件不匹配时，取消预演并以权威状态恢复。

## Risks / Trade-offs

- [客户端与云函数事件契约同时变化，旧客户端无法正确解释新字段] → 客户端与云函数同步发布，并在服务端部署后进行版本兼容检查。
- [静态弃牌状态提前提交，客户端可能在动画期间提前显示 mini 牌] → 渲染器根据当前事件的 card id 临时隐藏静态牌，直到动画交接完成。
- [等待牌已经回执但仍保留显示，容易被误认为仍在动画] → 将保留出现牌作为独立视觉状态管理，不挂载活动 Tween，也不参与动画屏障。
- [所有玩家选择“过”的流程与初始无人响应不同] → 保留最终归位事件，只合并服务端初始即可确定的无人响应分支。
- [完整牌组的大图动画可能覆盖桌面其他元素] → 依据安全区和中央可用区域计算组整体缩放上限，保持组内比例。
- [本地预演与权威事件不匹配会出现视觉回退] → 使用稳定操作标识进行确认，取消时清理临时隐藏和保留牌，再从权威快照恢复。

## Migration Plan

1. 先扩展公开事件模型、序列化和服务端测试，加入 `appearanceResolution` 与完整 meld 动画数据。
2. 实现客户端新动画状态机、目标布局解析和静态牌隐藏交接。
3. 更新服务端无人响应推进逻辑，移除“初始即无人响应”场景的独立 `unclaimed` 事件。
4. 联调四人在线牌局，覆盖有人响应、初始无人响应、所有人过和本地预演确认。
5. 客户端与云函数同步发布；如需回滚，整体回滚到旧事件协议和旧客户端动画实现。
